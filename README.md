# failclosed-toolkit

> 让 **AI 协作 / 无人值守自动化**不「静默出错」的**四个工具 + 一份方法论**。

纯标准库，零第三方依赖，Python 3.8+。

---

## 为什么做这个

失败分两种：

- **显性失败**：崩了、抛异常了 —— 会被人看见，可以修。
- **静默失败**：**没报错，但结果是错的** —— 没人发现，直到出事。

第二类才是难缠的。真实工程里反复撞见的是这四种：

| 静默失败 | 症状 |
|---|---|
| 脱敏**漏了一处** | 报告看起来干净，其实真值还在里面 |
| 自检**没跑**却打印「全部通过」 | 「假绿」：以为守住了，其实门是开的 |
| 任务**早就干完了，锁还占着** | 「假占用」：后续任务被无声地堵住 |
| 笔记**超了容量上限** | 「静默截断」：尾部的规则悄悄失效，不报错 |

本仓库把针对这四类问题的做法，抽成四个**与业务无关**的通用工具；
并把背后的判断写成了一份方法论（见 [§方法论](#方法论)）。

## 四个工具

### `redact` —— 脱敏 + 残留自检（fail-closed）

只做替换的工具**没法告诉你它漏了**。所以这里把两件事绑死：

```
替换 ──► 再扫一遍 ──► 有残留就抛错、不产出
```

- 用**精确词典**（已知真值）替换，不靠正则猜；
- **长值优先**，避免短值吃掉长值的子串；
- 词典之外的值用**上下文规则**兜底；
- `redact_strict()` 在有残留时抛 `LeakError` —— 宁可没有输出，
  也不输出「以为脱敏了、其实没脱干净」的东西。

### `checkgate` —— 检查器注册表 + 运行闸门（fail-closed）

把「有哪几项检查 / 失败算阻塞还是警告 / 显示什么文案」收口到**一个 JSON**，
加一项检查只改一处。四条 fail-closed 规则：

1. 注册表读不出来 ⇒ **整闸阻塞**（否则会「一项都没跑」却看着绿）；
2. 某项没声明 level ⇒ **按阻塞**；
3. 某项**超时** ⇒ **按阻塞** ——「判不了」绝不允许冒充「通过」；
4. 检查脚本不存在 ⇒ 明说「该项没检查」，**不算通过**。

### `reslock` —— 按资源分片的文件锁（带心跳）

- **分片**：不相干的资源不互相排队；不传资源名则退化为全局锁。
- **心跳**：只靠「pid 活着 + TTL」不够 —— 任务干完了、进程还留着时，锁会被白占满
  一个 TTL。持有方定期刷新 `beat`，等待方见 `beat` 过期即可接管。
- **安全判活**：Windows 上 `os.kill(pid, 0)` 会**真的把进程 TerminateProcess 掉**，
  所以走 `OpenProcess + GetExitCodeProcess`（见 `reslock.pid_alive`）。

### `contextbudget` —— 上下文预算守卫

笔记 / 记忆 / 指令文件超限后会被**按字符静默截断**，尾部的约束悄悄消失。
本工具量水位并预警：三态 `ok / near / over`（接近线默认 90%），
**只读不写**（守卫不该有副作用）。

```bash
# 单元测试（21 项）
python -m unittest discover -s tests -v

# 四个可跑示例
python examples/redact_demo.py

python examples/reslock_demo.py
python examples/contextbudget_demo.py     # 退出码 1：有文件超线

```

```
✓ 文档索引一致

⚠ 本机环境有缺口（不阻塞，但需显形）

判定：通过 1 / 警告 1 / 阻塞 1
```

## 方法论

四个工具背后是同一套判断。完整版写在
**[`docs/ai-collaboration.md`](docs/ai-collaboration.md)**，六条护栏：

| 护栏 | 一句话 |
|---|---|
| **fail-closed** | 判不了 = 不通过；「没跑成」不许冒充「跑通了」 |
| **单一真源** | 同一判断散落两处，就一定会静默漂移 |
| **验证独立于被测对象** | 自己检查自己 = 没检查 |
| **护栏要真跑** | 一个永远通过的检查器，比没有更糟 |
| **上下文预算** | 防静默截断，且接到既有必跑路径上 |
| **给 agent 写文档** | 歧义 = 静默失败；结论先行 + 写清边界与反例 |

还包括：**身份判据要用改不了的东西**（平台事实，而非可伪造的本地标记）、
**最小暴露**（真值不出门）、**多轮短跑**、**复杂度倒置**（复杂度留在有权限的一侧）。

## 从哪来

这四个工具是从一套**生产级自动化系统**里抽出的可公开子集。那套系统是这样的（已泛化）：

- 面向**多个外部 Web 平台**的数据采集与合规自动化；
- 数十个租户、几十个自动化任务、多台机器、**无人值守**定时运行；
- 由「调度 → 执行 → 守卫 → 数据」四层构成，守卫层负责并发、脱敏、发布前自检。

**规模与效果（可核）：**

| 指标 | 值 |
|---|---|
| 发布前一致性检查器 | 14 项（注册表驱动，加一项只改一处） |
| 自动化脚本 / 复用单元 | 80+ / 30+ |
| 批处理性能 | 150 个目标：**352s → 69s**（约 5×） |
| 静默失败 | 四类各有守卫 + 回归用例 |

> ★ **主系统代码不公开**：它含客户数据与商业流程，合规上不可外发。
> 本仓库只放**与业务无关**的通用部分。
