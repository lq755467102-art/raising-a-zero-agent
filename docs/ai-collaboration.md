# 与 AI 协作的工程护栏

> 长期让 AI agent 参与真实工程（写代码、跑运维、改文档）后，沉淀下来的一套做法。

---

## 本页速览

**核心命题**：AI 协作里最贵的失败，不是「它做错了」，而是 **「它做错了却没报错」** ——
于是没人发现，直到出事。

| # | 护栏 | 一句话 |
|---|---|---|
| 1 | **fail-closed** | 判不了 = 不通过；「没跑成」不许冒充「跑通了」 |
| 2 | **单一真源** | 同一判断散落两处，就一定会**静默**漂移 |
| 3 | **验证独立于被测对象** | 自己检查自己 = 没检查 |
| 4 | **护栏要真跑** | 要能证明它「抓得住」，而不只是「通过了」 |
| 5 | **上下文预算** | 防静默截断，且接到**既有必跑路径**上 |
| 6 | **给 agent 写文档** | 歧义 = 静默失败 |

另有四条配套：**身份判据要用改不了的东西** · **最小暴露** · **多轮短跑** · **复杂度倒置**。

---

## 1. `fail-closed`：判不了 = 不通过

**撞到什么**：自检脚本超时或被环境卡住，流程却打印「全部通过」——
「没跑成」被默认当成了「没问题」。

**怎么做**：

- 任何"没跑成"（超时 / 异常 / 读不出配置）**一律按阻塞处理**；
- 文案**显式**写「超时·判不了」，**不冒充内容结论**（免得和"内容有问题"混为一谈）；
- 退出码 0 的语义是「**没有阻塞项**」，不是「全绿」—— 判定行要把**警告条数**摆到眼前。

→ [`checkgate.py`](../zeroagent/checkgate.py)

## 2. 单一真源

**撞到什么**：同一个判断散落在两处（运行脚本一份、看板一份）。加一项检查要改两处，
**漏一处就静默少跑** —— 而且是安静的：另一处照样报一套看着正常的数。

**怎么做**：判据、集合、文案**收口到一个注册表**；加一项检查 = 只改一处，
运行方**只负责遍历**它。

→ [`checkgate.py`](../zeroagent/checkgate.py) 的注册表

## 3. 验证必须**独立于**被测对象

**撞到什么**：脱敏工具「替换成功」了，产物看起来干净 ——
但词典只覆盖**已知**值，文档里引用了**别的**同类值，它抓不到，**而且不会告诉你它抓不到**。

**怎么做**：替换之后**独立再扫一遍**（不是"再跑一遍替换"）；有残留就**抛错、不产出**。

> 这条救过场。**自己检查自己，等于没检查。**

→ [`redact.py`](../zeroagent/redact.py) 里那个「替换完再独立扫一遍」的函数（`residual()`）

## 4. 护栏必须**真跑**，且能证明它「抓得住」

**撞到什么**：写了检查器，却从没验证过它**真的会红**。
**一个永远通过的检查器，比没有更糟** —— 它给你虚假的安全感。

**怎么做**：

- 每个护栏**自带自测**；
- 自测里必须包含「**注入一个坏场景 ⇒ 它确实报红**」，而不只是"好场景通过"；
- 示例刻意留一个失败项，用它证明闸门**真的会拦**。

→ 九个模块的 `--selftest`；[`examples/checkgate_demo/`](../examples/checkgate_demo)（退出码刻意是 1）

## 5. 上下文预算：防**静默截断**

**撞到什么**：笔记 / 记忆 / 指令文件有容量上限。超了之后客户端**按字符静默截断** ——
尾部规则悄悄消失，**不报错、不提示**。
你失去的不是一次报错，而是「**某条约束从此不再生效**」。

**怎么做**：量水位（上限 + 接近线，默认 90%，三态 `ok / near / over`）·
**只读不写**（守卫不该有副作用）· ★ 挂到**既有必跑路径**上（提交前 / 发布前），**不新增定时任务**。

→ [`contextbudget.py`](../zeroagent/contextbudget.py)

## 6. 给 agent 写文档：**歧义 = 静默失败**

**撞到什么**：文档含糊时，agent **不会来问你** —— 它会"合理地"做错。

**怎么做**（也是本仓库文档自己的写法）：

- **结论先行**：第一段就说清"这是什么、解决什么问题"；
- **触发条件放最前**：让它一眼判断"该不该用我"；
- **写清边界与反例**：不只说"该做什么"，更要说"**不做什么**"；
- **给判据而不是形容词**：不说"尽量简洁"，说"默认 90%、超上限即阻塞"；
- **参数化而非写死**：容易变的（路径、上限、阈值）抽成配置。

---

## 7. 身份与权限：判据要用**改不了的东西**

**撞到什么**：用 `git config user.email` 判断「我是谁、能不能推保护分支」——
**改一行配置就能冒充**。

> 这条的教训是：**判定用的东西，必须是"自己想改也改不了"的**。
> 一旦用上自己能改的标记，再严谨的流程也只是纸面的 —— 而且它**看起来还在正常工作**。

**怎么做**：

- 身份靠**平台事实**判定（能否推保护分支、是否为该资源的 owner）—— **改不了**，因为由对端平台决定；
- 有**副作用**的操作走**审批**，不靠"我看起来是管理员"；
- 把「伪造判据」列为**明确的反例**写进文档，防止下一个人又用回去。

## 8. 最小暴露：真值不出门

**配置外置**（真值只在本机，不进仓库）· **提交前自查**（占位符 / 绝对路径 / 私钥块）·
**导出前脱敏** + fail-closed · 原则：**默认私有**，只有做成「与业务无关的通用件」才考虑公开。

> 本仓库本身就是这条原则的产物：**只有零业务的部分才被拿了出来。**

## 9. 节奏：多轮短跑

**宁可跳过重试，也不长时间静默阻塞** · 每步都要**可验证**、失败要**快速暴露** ·
长任务要么给上限（超时即阻塞），要么拆成能单独验证的小步。

## 10. 复杂度倒置

**复杂度留在有权限的人这一侧，面向使用者的一端要薄。**

| | 内部（我这边） | 外部（使用者） |
|---|---|---|
| 检查项 | 14 项 + 注册表 + 分片锁 + 心跳 | 一句命令，一个判定 |
| 概念 | 红/黄、fail-closed、单一真源 | 「✅ 可以推」/「✗ 先修」 |

换来的是：**非技术使用者不需要理解护栏，也能被护栏保护。**

## 落点表

| 原则 | 代码落点 |
|---|---|
| 判不了 = 不通过 | `checkgate` —— **发布前的检查闸门** |
| 单一真源 | `checkgate` 的登记表 —— 加一项检查只改一处 |
| 验证独立于被测对象 | `redact.residual` —— **脱敏后独立再扫一遍** |
| 护栏要真跑、能证伪 | 各模块自带的 `--selftest`（内置自测）+ 可跑示例 |
| 防静默截断 | `contextbudget` —— **量上下文水位，超线预警** |
| 资源不该被粗粒度互斥 | `reslock` —— 锁**按资源分片**，不相干的任务不排队 |
| 进程活着 ≠ 在干活 | `reslock` —— **持锁方打卡**（心跳） |
| 审批不能被绕过 | `approvalgate` —— **防"自己批自己"** |

---

## 诚实的边界

- 护栏只能保证「**没跑成不会冒充跑通**」，**不能**保证「检查项选得好」—— 后者仍靠人；
- 上下文预算工具**只报警**，蒸馏 / 精简还得人来；
- 这套做法来自**一台机器 + 一套系统**的实践，不是普适定理，换环境需要重新验证；
- 它防的是**静默失败**，不防**显性错误** —— 后者本来就会自己喊出来。
