# 与 AI 协作的工程护栏

> 长期让 AI agent 参与真实工程（写代码、跑运维、改文档），积累下来的一套做法。
> **核心命题**：AI 协作里最贵的失败，不是"它做错了"，而是**"它做错了却没报错"** ——
> 于是没人发现，直到出事。

这篇只讲**可执行的做法**：每条都写清「撞到什么 / 怎么解 / 落在哪个代码里」。

---

## 一、六条护栏

### 1. `fail-closed`：**判不了 = 不通过**

**撞到什么**：自检脚本超时或被环境卡住，流程却打印「全部通过」。
「没跑成」被默认当成了「没问题」。

**怎么做**：
- 任何"没跑成"（超时 / 异常 / 读不出配置）**一律按阻塞处理**；
- 文案**显式**写「超时·判不了」，**不冒充内容结论**（避免和"内容有问题"混为一谈）；
- 退出码 0 的语义是「**没有阻塞项**」，不是「全绿」——判定行要把**警告条数**摆到眼前。

**落点**：[`checkgate.py`](../failclosed/checkgate.py)。

### 2. 单一真源

**撞到什么**：同一个判断散落在两处（运行脚本一份、看板一份）。加一项检查要改两处，
**漏一处就静默少跑**——而且是安静的，另一处照样报一套看着正常的数。

**怎么做**：判据、集合、文案**收口到一个注册表**；加一项检查 = 只改一处。
运行方**只负责遍历**它。

**落点**：[`checkgate.py`](../failclosed/checkgate.py) 的 `registry.json`。

### 3. 验证必须**独立于**被测对象

**撞到什么**：脱敏工具"替换成功"了，产物看起来干净。
但词典只覆盖**已知**值，文档里引用了**别的**同类值——它抓不到，而且**不会告诉你它抓不到**。

**怎么做**：
- 替换之后**独立再扫一遍**（不是"再跑一遍替换"）；
- 有残留就**抛错、不产出**（fail-closed）；
- 上线前再做一次**人肉之外**的独立复核。

> 这条救过场：正因为"独立扫"，才发现一处词典之外的漏网值。
> **自己检查自己，等于没检查。**

**落点**：[`redact.py`](../failclosed/redact.py) 的 `residual()`。

### 4. 护栏必须**真跑**，且要能证明它"抓得住"

**撞到什么**：写了一个检查器，但从没验证过它**真的会红**。
一个永远返回通过的检查器，比没有检查器更糟——它给你虚假的安全感。

**怎么做**：
- 每个护栏**自带自测**；
- 自测里必须包含「**注入一个坏的场景 ⇒ 它确实报红**」，而不只是测"好场景通过"；
- 示例里刻意留一个失败项，用它证明闸门**真的会拦**。

**落点**：四个模块的 `--selftest`，以及 [`examples/checkgate_demo/`](../examples/checkgate_demo)（退出码刻意是 1）。

### 5. 上下文预算：防**静默截断**

**撞到什么**：笔记 / 记忆 / 指令文件有容量上限。超了之后，客户端**按字符静默截断**——
尾部的规则悄悄消失，**不报错、不提示**。
你失去的不是一次报错，而是「**某条约束从此不再生效**」。

**怎么做**：
- 量水位：每个文件配上限 + 接近线（默认 90%），三态 `ok / near / over`；
- **只读不写**（守卫不该有副作用）；
- ★ 挂到**既有必跑路径**上（提交前 / 发布前），**不新增定时任务**；
- 阈值走**单一真源**，别在别处再抄一份。

**落点**：[`contextbudget.py`](../failclosed/contextbudget.py)。

### 6. 给 agent 写文档：**歧义 = 静默失败**

**撞到什么**：文档写得含糊时，agent **不会来问你**——它会"合理地"做错。
这和超时、截断是同一类失败：**没人报错，但结果是错的**。

**怎么做**（这也是本仓库文档自己的写法）：
- **结论先行**：第一段就说清"这是什么、解决什么问题"；
- **触发条件写在最前面**：让它一眼能判断"该不该用我"；
- **写清边界与反例**：不只说"该做什么"，更要说"**不做什么**"；
- **给出判据而不是形容词**：不说"尽量简洁"，说"默认 90%、超上限即阻塞"；
- **参数化而非写死**：容易变的东西（路径、上限、阈值）抽成配置。

## 二、身份与权限：判据要用**改不了的东西**

**撞到什么**：用 `git config user.email` 判断"我是谁、能不能推保护分支"——
而**改一行配置就能冒充**。更糟的是，提供这套判定方案的文档里，开头就写着
「标记可以伪造，一个都不用」。

**怎么做**：
- 身份靠**平台事实**判定：比如「能否推送受保护分支」「是否是该资源的 owner」——
  这些**改不了**，因为它由对端平台决定；
- 有**副作用**的操作（改配置、花钱、发布）走**审批**，不靠"我看起来是管理员"；
- 把「伪造判据」列为**明确的反例**写进文档，防止下一个人又用回去。

## 三、最小暴露：真值不出门

- **配置外置**：真值（凭据、ID、人名）只在本机配置里，**不进任何仓库**；
- **提交前自查**：占位符有没有残留、绝对路径有没有混入、私钥块有没有带上；
- **导出前脱敏** + fail-closed（见护栏 3）；
- 原则：**默认私有**。只有在它被彻底做成「与业务无关的通用件」之后，才考虑公开。

> 本仓库本身就是这条原则的产物：**只有零业务的部分才被拿了出来。**

---

## 四、节奏：多轮短跑

- **宁可跳过重试，也不长时间静默阻塞**：一次跑不完就分批、缩短单步耗时；
- 每步都要**可验证**，失败要**快速暴露**，而不是等到最后一起炸；
- 长任务要么给上限（超时即阻塞），要么拆成能单独验证的小步。

---

## 五、复杂度倒置

**复杂度留在有权限的人这一侧，面向使用者的一端要薄。**

| | 内部（我这边） | 外部（使用者） |
|---|---|---|
| 检查项 | 14 项 + 注册表 + 分片锁 + 心跳 | 一句命令，一个判定 |
| 概念 | 红/黄、fail-closed、单一真源 | 「✅ 可以推」/「✗ 先修」 |

用它换来的是：**非技术使用者不需要理解护栏，也能被护栏保护。**

## 六、一句话落点表

| 原则 | 代码落点 |
|---|---|
| 判不了 = 不通过 | `checkgate` |
| 单一真源 | `checkgate` 的注册表 |
| 验证独立于被测对象 | `redact.residual` |
| 护栏要真跑、能证伪 | 各模块 `--selftest` + 示例 |
| 防静默截断 | `contextbudget` |
| 资源不该被粗粒度互斥 | `reslock` 分片 |
| 进程活着 ≠ 在干活 | `reslock` 心跳 |

## 七、诚实的边界

- 护栏只能保证「**没跑成不会冒充跑通**」，**不能**保证「检查项选得好」——
  后者仍然靠人；
- 上下文预算工具**只报警**，蒸馏 / 精简还得人来；
- 这套做法来自**一台机器 + 一套系统**的实践，不是普适定理；换环境需要重新验证；
- 它防的是**静默失败**，不防**显性错误**——后者本来就会自己喊出来。
