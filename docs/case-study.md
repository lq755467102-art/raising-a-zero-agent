# Case Study：让无人值守的系统「不静默出错」

> 一份 **fail-closed 设计**的实践记录。  
> 内容已泛化：不含客户、平台或业务细节，只保留**结构、判断与踩坑**。

---

## 本页速览

一句话：**这套系统最大的风险不是崩溃，而是「没崩、没报错，但结果是错的」。**

| 静默失败          | 根因                  | 设计                    |
| ------------- | ------------------- | --------------------- |
| 脱敏**漏一处**     | 词典只覆盖「已知」值          | 改为「替换 + **独立**自检」     |
| 自检**没跑却报通过**  | 判据散落两处 + 退出码 0 被当全绿 | 收口**单一真源** + 明示警告条数   |
| 锁**假占用**      | 「pid 活着」被当成「在干活」    | **按资源分片** + 持有方**心跳** |
| 笔记**超限被截断**   | 超限后按字符**静默截断**      | **上下文预算**守卫（只读）       |
| 危险操作**被静默放行** | 审批可被绕过（尤其**自批**）    | **审批闸门**：申请人≠审批人      |
| **重跑**出问题     | 重复副作用 / 跳步时用了过时输入   | **幂等 + 输入指纹**         |

---

## 1. 背景

| 维度   | 情况                                 |
| ---- | ---------------------------------- |
| 形态   | 面向多个外部 Web 平台的数据采集 + 合规操作，浏览器自动化驱动 |
| 规模   | 数十个租户；80+ 脚本、30+ 复用单元；多台机器         |
| 运行方式 | **无人值守** —— 定时触发，**出事时人不在场**       |
| 关键约束 | 数据敏感，**产出物不得含真值**；错一次代价很高          |

「无人值守」把容错的标尺整个抬高了：**没有人会在旁边发现异常**。  
系统必须自己保证「**没把握的时候，宁可停下，也不假装成功**」—— 这就是 fail-closed。

---

## 2. 六类静默失败（都是真实撞见过的）

### 一：脱敏「漏一处」

最初的做法就是「拿到真值列表 → 逐个替换」。问题是：**这个工具没法告诉你它漏了。**

> 真实案例：人工复查时发现，某条日志里写着「实测通过（账号 10000001）」——  
> 该账号**不在**本机配置里，脱敏词典根本没覆盖它。  
> 替换逻辑「成功」了，产物「看起来」是干净的。

**根因**：词典只覆盖**已知**值，而文档可能引用**别的**同类值。**替换成功 ≠ 干净。**

### 二：自检「没跑却报通过」（假绿）

推送前有一道闸门。早期它把判据**手写在两处**：运行脚本一份、健康看板一份。  
加一项检查要改两处，漏一处就**静默少跑**；更糟的是判定行**无条件打印「✅ 可以推送」**。

> 真实案例：一次新加的检查器，失败分支被写成了「警告」而非「阻塞」。  
> **真缺陷以「能推」的形式过去了** —— 退出码 0，看起来一切正常。

**根因**：① 判据散落 ⇒ 静默漏跑；② **「没有阻塞项」被当成了「没有问题」。**

### 三：锁「假占用」

任务之间要互斥，最初是一把**全局锁**：一开就跑，持到脚本结束。

> 真实案例：运行机制变化后，**脚本跑完、进程却留着等会话复用** ⇒  
> 业务早完成了，锁还占着，**白占满整个 TTL（45 分钟）**，后续任务被无声堵死。

**根因**：**「进程活着」≠「还在干活」。** 另一个坑：粒度太粗 ——  
两个**不碰同一资源**的任务也被迫排队。

### 四：笔记「超限被截断」

笔记 / 指令文件有容量上限。超了之后，客户端**按字符静默截断**：尾部的规则悄悄消失。

**根因**：你失去的不是一次报错，而是「**某条约束从此不再生效**」——  
而且**没有任何提示**。尺子早就有，但**没有任何东西在跑它**。

### 五：危险操作「被静默放行」

**根因**：最隐蔽的一种绕过是 —— **申请人自己把申请批了**。  
形式上"审过了"，实质上等于没审。

### 六：重跑「重复副作用 / 跳错步」

任务中途失败后重跑，两种朴素做法**都不安全**：从头再来**会重复执行有副作用的步骤**；  
跳过"看起来做过"的步**可能跳错**（输入其实变了）。

**根因**：判据里没有**输入**。「这步的名字」不能证明「这步的输入没变过」。

## 3. 设计与取舍

### 决定一：把「有哪几项检查」做成**单一真源**

所有一致性检查及其「红/黄」「显示文案」收口到**一个 JSON**，运行方与看板**都读它**。  
加一项检查 = 只改一处。

**判据原则**：坏的是「**要推上去的东西**」⇒ 阻塞（✗）；  
坏的是「**本机环境 / 远端状态**」⇒ 警告（⚠）（显形，但不阻塞）。

**★ 但数据化引入了新风险**（本篇最关键的一段）：

> 把「跑哪几项」从**硬编码**换成**读注册表**后，原来那 13 个手写块是**被挑选过的**  
> —— 它们都不会挂住。数据化把这层**隐含保护**移除了：  
> 谁往注册表里写一个「读 stdin / 卡在网络上」的检查器，这一步就会跟着一起挂。

**补法**：给每次调用加**单步超时**，且**超时按阻塞处理**；文案显式写「超时·判不了」，  
**不冒充内容结论**。

> **教训：抽象化会移除原先靠「人工挑选」提供的隐含保护 —— 必须显式补回。**

### 决定二：判定行不再无条件打「✅」

把**警告条数**摆到眼前：只有 `0 阻塞 / 0 警告` 才叫 ✅；  
即使退出码 0，也明确写「**能推 ≠ 全绿**」。

### 决定三：锁从「全局互斥」改成「**按资源分片 + 心跳**」

- **分片**：盘点实际用到的资源，发现**只有一个是真正的共享资源**，其余自带租户标识、  
  本不需要互斥 ⇒ 锁按资源名分片，不同资源互不阻塞；  
  不传资源名则退化为全局锁（**向后兼容**）。
- **心跳**：持有方定期刷新 `beat`，等待方见 `beat` 过期即可接管 ——  
  不必等 pid 死、也不必等 TTL。真还在跑时 `beat` 一直是新的，**绝不会被误抢**。

**★ 一个跨平台坑**（要解决的事：判断某个进程还活着没有 —— 用来回收被僵尸进程占住的锁）：

> 原实现是 Node，用 `process.kill(pid, 0)` —— 传 `0` 表示「**只探测、不发信号**」，安全。  
> 照搬到 Python 写成 `os.kill(pid, 0)`（名字几乎一模一样）—— **在 Windows 上会把那个进程真的杀掉**：  
> Python 的 `os.kill` 只对 `CTRL_*`（Ctrl+C 那一类控制信号）有特殊语义，其余值**包括 `0`** 一律走「强制终止」。  
> ⇒ 必须改用 `OpenProcess` + `GetExitCodeProcess` —— 这两个系统接口**只查询状态、不发信号**，绝不会误杀。
>
> **同名 API ≠ 同义 API。安全相关的调用必须逐条查文档。**

### 决定四：脱敏从「替换」升级为「**替换 + 独立自检**」

精确词典（不靠正则猜）· **长值优先**（否则 `A` 先替 ⇒ `AB` 变成 `<占位>B`）·  
词典外的值用**上下文规则**兜底 · **替换完再扫一遍**，有残留就**抛错、不产出**。

### 决定五：危险操作加**审批闸门**

只有 `approved` 放行（未知 / 不存在 / 已驳回 ⇒ 不放行）·  
**申请人 == 审批人 ⇒ 拒绝并记审计** · 同人同内容**幂等** · 全程留痕。

## 4. 结果

| 指标           | 值                                |
| ------------ | -------------------------------- |
| 发布前一致性检查器    | **14 项**（注册表驱动，加一项只改一处）          |
| 自动化脚本 / 复用单元 | 80+ / 30+                        |
| 批处理性能        | 150 个目标：**352s → 69s（约 5×）**     |
| 抽取出的可公开工具    | **6 个**（本仓库 `zeroagent/`）       |
| 测试           | 单元测试 **34 项** + 内置自测 **67 项**，全绿 |

六个工具**都带自测**，且自测里包含「**注入一个坏场景 ⇒ 它确实报红**」；  
示例也刻意如此（`checkgate` / `contextbudget` 两个示例**退出码为 1**，用来证明它真的会拦）。

## 5. 可迁移的判断

1. **「判不了」必须和「不通过」一样对待。**  
   超时、异常、缺配置 —— 只要没跑成，就不能算通过。否则**守门人本身就是漏洞**。
2. **抽象化会移除隐含保护，要显式补回。**  
   把硬编码换成配置，顺手也把「人工挑选」的安全余量换没了。要主动问：  
   *原来靠什么保证它是安全的？那个东西还在吗？*
3. **验证必须独立于被测对象。**  
   残留检查不是「再跑一遍替换」，而是**独立再扫一遍** —— 也正因如此才抓到了漏网的值。  
   **自己检查自己，等于没检查。**
4. **判据要有单一真源。** 同一判断散落两处，就一定会漂移，**而且是静默漂移**。
5. **「进程活着」≠「在干活」；「没报错」≠「没问题」。**  
   这两句几乎概括了全篇的动机。

---

## 6. 局限与下一步

- `redact` 的兜底规则仍需按场景定制，不是放之四海皆准；
- `reslock` 是**单机**文件锁；跨机器需要换成分布式租约（带过期的 KV）；
- `approvalgate` 默认存储是单机 JSON，多人并发要换数据库；
- **闸门只能保证「没跑成不会冒充跑通」，不能保证「检查项设计得好」** —— 后者仍靠人。
