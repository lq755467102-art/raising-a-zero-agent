## 二、失败与守卫（要防的是什么）

| 术语 | 一句话 | 详见 |
|---|---|---|
| **静默失败** | **没报错，但结果是错的。** 崩溃会喊，它不会 —— 你发现它的时候往往已经晚了 | [README](../README.md) |
| **fail-closed** | **拿不准的时候，默认「不放行」。** 一句话：「我不知道」绝不允许被当成「没问题」 | [AI 协作 §1](ai-collaboration.md) |
| **假绿** | 检查器**没跑成**，输出却是"全绿" | [case study §2](case-study.md) |
| **假占用** | 任务早就干完了，锁还占着 —— 后续任务被**无声堵住** | [case study §2](case-study.md) |
| **会红的用例** | 一个能**证明"它真的会拦"**的用例（而不是"它通过了"） | [AI 协作 §4](ai-collaboration.md) |
| **失败分类学** | 失败按「显性/静默 × 可恢复/不可恢复」分四类。★ **静默失败那一格是空的** —— 它只能预防，没法处置 | [系统设计 §3](system-design.md) |

## 三、漂移（东西为什么会走样）

| 术语 | 一句话 | 详见 |
|---|---|---|
| **漂移** | 改动之后，判据/文档/行为/版本**多处不同步**。高频迭代 = 高频漂移，躲不掉 | [漂移](drift.md) |
| **认知漂移** | AI 在**实现层**理解一个功能，人在**意图层**理解它 —— **两边会在交流中分岔，而且双方都以为对齐了** | [认知漂移](cognitive-drift.md) |
| **实现层 / 意图层** | AI 关心"怎么写、数据怎么流"；人关心"为什么要有它、服务于什么结果" | [认知漂移 §一](cognitive-drift.md) |
| **真源** | 「什么是对的」这件事，**由谁来定义** | [认知漂移 §四](cognitive-drift.md) |
| **真源分域** | ★ **代码域的真源倾向模型**（训练量碾压）；**业务域的真源只能由人定**（取决于人的诉求） | [认知漂移 §四](cognitive-drift.md) |
| **Spec-Impl Misalignment** | 代码**完全满足字面规格**，却没解决真实问题 —— 一种新类型的 bug | [认知漂移](cognitive-drift.md) |

## 四、操作原则（遇到事怎么判）

| 术语 | 一句话 | 详见 |
|---|---|---|
| **单一真源** | 同一条判据**只有一处**。写两处就一定会漂，而且是静默漂 | [AI 协作 §2](ai-collaboration.md) |
| **红绿验证** | 把「我以为你懂了」变成**一个能变红的用例** | [认知漂移 §五](cognitive-drift.md) |
| **逆向验证** | 拿到结果**先找不合预期的地方**，再**溯源它怎么产生的** | [README ⑤](../README.md) |
| **独立复核** | 验证者**不能是被测对象自己** —— 自己检查自己等于没检查 | [AI 协作 §3](ai-collaboration.md) |
| **行为等价性** | 重构时先跑基线，改完**逐行比对**。判据不是"看起来对"，是"**与基线一致**" | [安全变更 §1](changing-safely.md) |
| **不要用语言对齐** | 用一个**会变色**的东西对齐（红绿验证 = 原型 > 语言，同一招） | [认知漂移 §五](cognitive-drift.md) |
| **复杂度倒置** | 复杂度**留在有权限的那一端**（管理端），使用者那一端做薄 | [AI 协作 §10](ai-collaboration.md) |
| **多轮短跑** | 小步快跑，宁可**多轮重试**，不单轮长时间阻塞 | [AI 协作 §9](ai-collaboration.md) |
| **最小暴露** | 真值不出门：业务值不入库、凭据不进仓库 | [AI 协作 §8](ai-collaboration.md) |
| **只增不删** | 用「定期人工清理」换「**永不误删**」 | [安全变更 §3](changing-safely.md) |

## 六、关于人（带教者需要什么）

| 术语 | 一句话 | 详见 |
|---|---|---|
| **懂业务** | 三条：知道**不能碰什么**（红线）、知道**什么才算对**（验收）、而这两件事**只有他能说了算**（真源） | [README §一](../README.md) |
| **架构直觉** | 在**看不清全貌**的时候，仍能判断"什么对这套系统有用"并动手试 | [README §二](../README.md) |
| **强提问 / 弱提问** | 强提问会逼出「**可证伪的期待**」（"我认为应该是 X，你去验证"）；弱提问拿到答案就停了 | [README §三](../README.md) |
| **能被固化的提问** | 提问若解决后能**沉淀成机制** ⇒ 在培养 AI；只是"帮我做掉" ⇒ 只是在用 AI | [README §三](../README.md) |
| **不敢说** | 人最怕的不是"想不出来"，是"**我说不清楚**"。它掐住的正好是**输入端** | [README §三](../README.md) |
| **模型的隐含真源** | 模型自带的海量训练经验，是**代码域**可用的第三方参照 —— 但它**没有出处**，不能当证据链的一环 | [0 号 AI §三](zero-agent.md) |

## 用法建议

- **读第一篇之前**：扫一遍这一页的"一句话"，不求记住。
- **读到卡住时**：回来查这个词，点链接跳过去看详细。
- **写完东西之后**：如果引入了新词，**回来加一行** —— 否则它会变成下一个"我不知道它具体做什么"的词。
