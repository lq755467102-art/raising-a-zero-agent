# 记忆漂移：同一套规则，怎么长成了五份互不知情的文件

> 本页记录的不是「AI 记性不好」，而是**记忆的存放位置本身就是漂移源**。
> 全部结论来自一次真实排查（一台跑了 10 天的机器，9 个定时任务 + 若干交互会话）。
> **它解释了一个此前被归因为「换了个模型所以变笨」的现象。**

---

## 一句话结论

1. **记忆的落点是「工作目录」的函数** —— 不是「一份文件的多个副本」，而是**每个工作目录一套**。⇒ 换目录 = 分叉，复制目录 = 复制后再各自生长。
2. **常驻注入有上限，超限静默截断** —— 所以「分叉」和「截断」会**叠加**：你读到的是**某个工作区那份的、被砍过的**版本。
3. **因此「薄指针指向唯一真源」是对的，但只写进记忆里不管用** —— 因为**指引本身也在被截断的内容里**。它必须写进**每次必读、且本身不被截断**的那一层。

---

## 一、现象：一次「新模型失忆」引出的排查

**症状**：换一个模型接手同一套系统，它的表现是——**完全不知道系统里已固化的规则**，
退化成「只会做眼前这一件事」的单一任务型助手，需要人工再纠错一轮。

**第一反应**通常会归因到模型差异。**但这里有个更简单的假设**：

> 规则都写在文件里，文件不会因为换模型而变化。
> **变的只可能是「新模型拿到的那份内容」** —— 它被截断过。

**排查办法**（不要靠回忆，靠一条命令把所有落点找齐 —— 见 §六）：

```bash
# 找齐所有记忆落点（示例，按自己的目录改）
find <工作目录根> -maxdepth 5 -name "MEMORY.md" -not -path "*/node_modules/*"
```

**结果（5 份，互不知情）**：

| # | 落点 | 体积 | 最后改动 | 谁在读（由证据反推） |
|---|---|---|---|---|
| 1 | 交互会话工作区 | 16.9 KB | 10-14 | **人机对话的那个会话** |
| 2 | 旧部署位（迁移前） | 18.8 KB | 10-15 | 迁移后已冻结 |
| 3 | 某专项会话工作区 | 14.3 KB | 10-15 | **那个专项的自动化任务** |
| 4 | 另一个迁移后的新会话工作区 | 0.3 KB | 10-15 | 那个会话（几乎是空的） |
| 5 | 现役部署位 | 15.4 KB | 10-15 | **大部分定时任务** |

**而且这还只是「人看的」那一层。** 另有一层**任务级记忆**（每个定时任务一份），
共 8 份，其中**最大的一份 266 KB / 1710 行**（≈ 常驻记忆的 16 倍）。

> ⚠ 关键：**这 5 份的内容彼此不同**。它们不是副本关系，是**五个不同工作区各自的记忆** ——
> 谁也不知道另外四份里写了什么。

## 二、机制：为什么「必然」分叉（不是谁写错了）

把落点规则写出来就清楚了：**记忆落在「当前工作目录」下**，任务级记忆同理。

⇒ 于是有三条推论，全部被实测印证：

| 推论 | 证据 |
|---|---|
| **① 换工作目录 ⇒ 记忆分叉** | 同一个任务 id 在**两个**工作区各有一份任务记忆，且**都在被写**（另一份停在更早的日期） |
| **② 复制目录 ⇒ 记忆被复制，然后各自生长** | 迁移后，旧位那份**冻结在 240 KB**，新位那份**继续长到 266 KB** |
| **③ 任务散落在不同工作目录 ⇒ 天然多套记忆** | 9 个定时任务分布在**至少 3 个**工作目录 ⇒ **3 套互不知情的规则** |

**第三条最要命**：任务 A 和任务 B 都属于同一个业务、本该共享同一套规则，
但它们的工作目录不同 ⇒ **各自读各自那份，各自写各自那份** ⇒
**「同一套规则」在物理上已经不存在了**。

### 再叠加上限

常驻记忆是**每次会话都注入**的，这本身是设计使然（省 token，也避免上下文拥挤）。
代价是**它有上限**，而且**超限是静默截断**——不报错、不告警、不告诉你是哪一段没了。

⇒ **两个机制叠加的结果**：

```
分叉  ⇒  你拿到的是「某个工作区那份」
截断  ⇒  而且是「被砍过的那份」
```

**这就是「新模型失忆」的真实形状**。不是它笨，是**它拿到的规则不全，而且没人知道不全**。

## 三、三种失效形态（都实测到）

| 形态 | 表现 | 为什么危险 |
|---|---|---|
| **A. 截断** | 最大的那份 266 KB，远超注入上限 | **尾部规则静默消失**。而人的直觉是「文件在 = 规则在」 |
| **B. 分叉** | 同一条任务有两份记忆，一份停在更早日期 | 两边**都在正常写**，看起来都健康 |
| **C. 复制后腐败** | 迁移时整目录复制 ⇒ 旧副本冻结但仍在 | 下次有人读到**旧的那份**，会以为「我读过记忆了」 |

⇒ 三种都属于同一个病：**没报错，但结果是错的**。

## 四、我们试过、但没落地的方案（诚实记录）

**方案本身是对的**：*单一真源 + 薄指针* —— 规则只写一处，各工作区只留「我是谁、去读哪儿」。

**但没落地。** 两条证据：

1. **入口文件里没有任何「动手前先读记忆」的规则**（实测 grep 结果：0 条）。
   ⇒ 于是**没有任何机制保证**那个指针被跟随过。**薄指针写在记忆里 = 谁都不读的注释。**
2. **反面证据更值得记**：那份记忆**自己**第一行就写了「会话启动：先读本文件 + …」。
   ⇒ 看上去已经是「自指向」了 —— **但这是自指向的陷阱**：

> **指引与被指引的内容同命。** 一旦这份记忆被截断，**那句「先读本文件」很可能就在被砍掉的那一段里**。
> 于是**指引消失得和它要保护的规则一样早**，而且**一样静默**。

⇒ **结论（本页最重要的一条）**：
**自指向必须放在「永不被截断的那一层」** ——
也就是**每次必读、且不参与容量竞争**的位置（项目入口文件 / 系统级约定），**不能放在记忆文件内部**。

## 五、构想：分层 + 多级指针（自指向）—— 可行性评估

在承认「常驻有上限」的前提下，有一个不变式：

> **只有「根」必须常驻、必须严格有界；其余层可以无限嵌套。**
> 换句话说：**容量问题不是「总量有界」，而是「根有界」。**

⇒ 所以「二级指针」不是可选技巧，**而是必然形状**（本质是目录树 / B 树）：

```
根（常驻，严格有界：只有"去哪找"）
 └─▶ 一层目录（分片索引：每片一行，指向正文）
      └─▶ 正文（无限，按需读）
           └─▶ 当正文本身也太大时：再套一层目录 ……（自指向）
```

**但必须承认三个死结**：

| # | 死结 | 只能这么解 |
|---|---|---|
| **1** | **跟链需要「读协议」**：指针不会自己生效，模型必须真的去读 | 靠**外层硬规则** + **检查器**。绝不能靠"记忆自己说"（见 §四） |
| **2** | **每一跳都有代价**（一次工具调用 + 一段上下文） | 指针必须**只指路、不复述**。**指针一旦开始复述内容，它自己就会变胖**，于是需要"给指针的指针"——这正是自指向的必要性来源，也是它失控的方式 |
| **3** | **断链必须 fail-closed** | 指向的目标不存在 ⇒ 报「不知道」，**不许**当作「这里没有」 |

**什么情况下不值得做**：如果规则总数**没超过根预算**，做多级指针是**自找复杂**。
（本项目是在「一份任务记忆长到 266 KB」之后才需要的。）

### 一个最小可行形状

```markdown
<!-- 根（每次必读，严格限行数；只有地址，没有内容） -->
- 业务规则：见 memory/INDEX.md → 「口径 / 阈值 / 推送」
- 改代码前：读 AGENTS.md
- 记忆分层说明：见 docs/memory-drift.md
```

**配套检查（缺一不可）**：

1. 根的**行数**是否超预算？（超 ⇒ 把一段挪进下一层，并把根里那一行改成地址）
2. **每个地址的目标是否存在**？（断链 ⇒ 立刻报，不许静默）
3. **同一主题是否出现了第二份**？（出现了 ⇒ 这就是分叉的起点，立即合并）

## 六、可复用的判据（直接抄）

**判据 1｜找齐落点**（别问人，问文件系统）

```bash
find <工作目录根> -maxdepth 5 -name "MEMORY.md" -not -path "*/node_modules/*"
```

**判据 2｜逐份体检**（对每一份）

| 检查 | 通过条件 |
|---|---|
| 体积 vs 注入上限 | **有明确余量**（贴线 = 已经在静默丢内容） |
| 最后改动时间 | 与"最后一次真实运行"**对得上**（对不上 ⇒ 它是冻结副本，别读它） |
| 同目录下是否有任务级记忆 | 有 ⇒ 一起体检（任务级更容易长成巨物） |

**判据 3｜查分叉**：**同一个任务标识，是否在多个工作目录下都有记忆？** 有 ⇒ 分叉已发生。

**判据 4｜查读协议**：**入口文件里，是否存在一条硬规则要求在动手前读记忆？**
没有 ⇒ **"真源"等于没被引用**（本项目的真实缺口就是这个）。

**判据 5｜查断链**：根的每一条地址，**目标是否存在**。断一条都不算通过。

## 七、诚实的边界

- **样本 n = 1 台机器**、10 天。落点规则是从**证据**反推的（同一任务多份记忆 + 冻结/生长对比），
  **不是**从平台源码读出来的 ⇒ **平台版本变化可能改变这一行为**。
- **多级指针的收益未验证** —— 它在本项目里**还只是构想**，本文只给出形状与判据，**没有实测数据**。
- 本页**只讨论"记忆放哪儿"**，不讨论"记忆里该写什么"。后者见 [漂移](drift.md) 与 [认知漂移](cognitive-drift.md)。
- 我们**没有**在多平台上复现。如果别的平台行为不同，欢迎用 §六 的判据去验，**结论以实测为准**。
