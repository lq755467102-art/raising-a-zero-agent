# 记忆树的同行：同类实践与研究

> 这篇回答一个问题：**「根有界 + 层按需读」这套形态，市面上有没有人在做？做到哪一步？**
>
> ★ **检索结论，不是世界事实**：下面是 2026-10 的一次检索（英文为主），
> 凡是说「**没有找到**」的，意思是**这次检索没找到** —— 不是「不存在」。
>
> ⚠ **来源可信度分三档**，正文逐条标注：`[一手]` 官方文档 / 论文原文；`[二手]` 博客、百科、解读；
> `[存疑]` 拿不到一手出处、或数字像是营销文案（**不要当数据用**）。

---

## 零、一句话结论

**「文件树 + 索引 + 按需读」这个形态已经不是独创，而且正在收敛成事实做法** ——
至少四家在几乎同一个结构上独立走到了这里（其中一家是官方产品）。
但我们有**三处**在这次检索里**没有找到同等完整度的**：**设计期声明式路由**、
**「检查器 + 人裁决」的验证纪律**、以及**注入点靠实测而非假设**。

⇒ 换句话说：**结构不新，纪律是新的**。

## 一、最同构的四家（几乎同一个东西）

### 1.1 `[一手]` Claude Code 的 auto memory（官方产品，最直接的同构）

来源：Anthropic 官方文档《How Claude remembers your project》（`code.claude.com/docs/en/memory`）。

| 它怎么做 | 我们的说法 |
|---|---|
| `MEMORY.md` 作**索引**，**首 200 行或 25KB**（谁先到算谁）在**每次会话开始**加载，**超出部分不加载** | 根有界 + 注入预算 |
| **主题文件**（`user_role.md` / `feedback_testing.md`）**启动时不加载**，Claude 需要时用文件工具按需读 | **层按需读**（`tree/` 不注入） |
| 写入后**度量**：接近上限 ⇒ 提醒「缩短它，把细节挪进主题文件，合并或删掉过期条目」；**超限写入仍成功，但报错要求重写索引**（因为下次加载会被丢弃） | ★ 与我们的「超限报红 + 人工裁决」同构 |
| 有 frontmatter 的记忆文件会记 **`modified`（ISO 8601 写入时间）**，让"这条事实有多新"可见 | 「必须署名 + 时间」 |
| `/memory` 列出**加载了哪些文件**、`/context` 看**实际进了上下文的有哪些** | 「人工三问」（开新会话问它读了什么） |
| **不跨机器 / 不跨云共享**；同一仓库的 worktree 与子目录**共享一份** | 「T0 跟账户走，clone 带不走」 |

★ **一处我们不如它**：它把「超限」的**度量与提醒**做进了**写入路径**（写一次量一次），
而我们是**定时 + 推送前**两处扫描。它更及时；我们覆盖面更广（还能查别的根）。

### 1.2 `[一手]` Anthropic Agent Skills：**渐进式披露**（方法论层面的同一句话）

来源：Anthropic 工程博客《Equipping agents for the real world with Agent Skills》＋ `platform.claude.com` 文档。

三级加载：

| 级 | 内容 | 何时进上下文 | 成本 |
|---|---|---|---|
| 1 | YAML frontmatter（`name` + `description`）| **常驻** | ~100 token / 技能 |
| 2 | `SKILL.md` 正文 | 被**触发**时读入 | < 5k token |
| 3 | 随附文件 / 脚本 | **引用时才读**；脚本只把**输出**带回来 | 按需 |

原文那句几乎就是我们的主张：

> *"the amount of context that can be bundled into a skill is **effectively unbounded**"*
> （能塞进一个技能里的上下文体量，**实际上是无界的**）

比喻也一样：**「先目录，再章节，最后详细附录」** —— 即"根有界、层可增殖"。
2025-12-18 起作为**开放标准**发布（`skill.md`）。

★ **关键分歧（也是我们最独特的一点）**：**触发靠什么？**
- **它**：靠 `description` **让模型自己判断**「这个技能是否相关」⇒ **运行时判断**；
- **我们**：靠**设计期声明** `reads: L1, L2` ⇒ **明说，不让运行时猜**。

我们为此写的理由（"运行时是没有资格判断的时刻"）**在这次检索里没有找到对应说法** ——
这一条可以算我们的**真实差异**。

### 1.3 `[二手]` Bonsai Memory：**几乎一字不差的「记忆树」**

来源：一篇中文技术解读（CSDN/DevPress，2026）。**未找到其一手仓库**，所以按二手记。

- **根索引（常驻，~400 token）→ 领域 `_index.md` → 叶子文件**；
- **最坏 3 次读取**（根 → 分支 → 叶子，约 750 token）；
- 它的**叶子定义**和我们几乎一样：

  > *「叶子文件（Leaves）：原始记忆被拆分后的一个个独立 Markdown 文件，
  > **每个文件对应一个逻辑上独立的知识单元（通常由 `##` 标题界定）**」*

- 启动加载从 **O(n) → O(1)**，而"跨领域搜索仍是 O(n)（因为它本来就要扫全部）"；
- 明确论证了「**为什么用文件树而不是向量库**」：零依赖、可移植、透明可调试、git 可版本化。

★ 这正是我们 `§2.3` 那条"**叶子升格成目录节点**" —— 连"按 `##` 小节切"都撞上了。
（我们的差异在**验证侧**：它有索引，我们还有一套查"断链 / 孤儿 / 超限"的检查器。）

### 1.4 `[二手]` Markdown Agent Memory：**路由索引 + 四条写入规则 + 一个 linter**

来源：GitHub `ucsandman/markdown-agent-memory`（作者自述**跑了 7 个月生产、跨 3 个模型 2 个厂商**）。

- `MEMORY.md` 是**路由索引**：**只放指针、不放事实**，**硬上限约 15,000 字符**；
- 读取路径：**启动只读身份文件 + 索引**；其余**任务触发时按"最窄文件优先"读**；
- **四条写入规则**（每条都值得对照，见 §三）；
- 还带一个 **linter**（`memory-lint`）。

> ⇒ 说明「索引 + 按需读 + 写入纪律 + 检查工具」这套**组合**，至少已经有人独立走完过一遍。

## 二、逐条对应：我们的说法 ↔ 市面上的名字

| 我们的说法 | 市面上的说法 / 实现 | 出处可信度 |
|---|---|---|
| **根有界、层可增殖** | Progressive disclosure（三级加载，"can be bundled … effectively unbounded"）| `[一手]` Anthropic |
| **根 ≤ 40 行 / 4KB** | `MEMORY.md` 首 200 行 / 25KB；另一份实现给 **~15,000 字符**硬上限；还有的给「文件 ≤ 50 行」| `[一手]`/`[二手]` |
| **`tree/` 不注入、按需读** | 主题文件"启动时不加载，按需用文件工具读" | `[一手]` Claude Code |
| **`reads:` / `may_read:`** | `.claude/rules/*.md` 的 **`paths:` 前置字段**（只在碰到匹配文件时加载）；另一份实现给每个索引行配"**一行说何时读它**" | `[一手]`/`[二手]` |
| **叶子 = 一次能读完的正文** | 「叶子 = 一个逻辑独立知识单元，**通常由 `##` 标题界定**」 | `[二手]` Bonsai |
| **叶子太大 ⇒ 升格成目录节点** | 递归摘要树（RAPTOR：在摘要之上再摘要，"直到进一步聚类不可行"）| `[一手]` 论文 |
| **断链 / 孤儿正文 / 叶子超限三项检查** | 一个"图健康检查"：报 **dangling links / orphans（没有索引指向的笔记）/ missing file links** | `[二手]` 博客（三条**全撞**）|
| **根 → 层 → 正文，两跳到位** | **H-MEM**：四层（Domain / Category / Memory Trace / Episode），**逐层路由指针、不做穷尽相似度计算** | `[一手]` 论文 |
| **"不知道它产出会不会错"判据** | 「**同类判断只能有一个权威来源**」这句我们也有；他们表述为 scope 匹配（`sources/web/**` 归哪个节点）| `[二手]` |
| **超限报红 + 人裁决** | 超限**报错并要求重写**（但是**让模型自己改**，不是交人裁）| `[一手]` Claude Code |
| **"只写事实与判据、不抄流水"** | 「**Knowledge, not events**」；另一份写「只存**不可重新推导**的东西」| `[二手]` ×2 |
| **记忆不在 git / clone 带不走** | "auto memory 是**机器本地**的；**不在机器或云环境之间共享**" | `[一手]` Claude Code |
| **跨机器同步要另走通道** | 未找到把"跨机共享记忆"做成一等公民的官方方案（**我们这条也是自建**）| — |

## 三、同行踩过的坑：这几条可以直接白捡

前三档是**别人明确写下来的规矩**，且**我们目前没有**：

| # | 规矩 | 为什么值得抄 |
|---|---|---|
| 1 | **Supersession 是「编辑」，不是「追加」** —— 改了一条决定，就**划掉旧的、在旁边写新的**（带日期），**永不删历史，也永不留两个未划掉的版本** | 我们只说了"不抄流水"，**没说"旧结论怎么办"**。他们的做法让"**现在信什么 / 以前信什么 / 凭什么**"三件事在**同一处**可读 |
| 2 | **每个事实带 provenance 标签**：`[stated]`（本人明说）/ `[observed]`（工具输出里看到）/ `[inferred]`（自己推的）/ `[suggested]`（自己提的、对方没答应）| 直接治我们的 **Q3 那类病**（"凭印象给量" —— 那句错话如果当初标了 `[inferred]`，一眼就能看出它没有实测支撑）|
| 3 | **推断出的教训要过「复发门」**：`3+` 独立信号、跨 `2+` 个不同会话，才升级为常驻规则（30 天前的信号算半）；**本人明确纠正的直接生效** | 我们已经有"同一条只记首次 + 计数"，但**没有"够不够格升级"这一层** |
| 4 | `[一手]` **Context Rot 的实测**：18 个模型，输入越长**非均匀衰减**；单个**语义相近的错误片段**就能拉低准确率，4 个干扰项会叠加 | ★★ 它修正了我们一条判断的**强度**：我们写"**读多了只是浪费**"；实测是"**读多了会降低准确率**"。⇒ 「读对层」不只是省钱 |
| 5 | `[一手]` **JetBrains（arXiv 2508.21433）**：**"遮掉旧工具输出"** 比 **"摘要重写"** 便宜且更好（约 **−52% 成本**、**+2.6% 解决率**）| 我们的轮转/蒸馏偏"摘要"一侧；**"直接遮掉旧的、保留一行记录"更便宜** —— 值得加一条通道 |
| 6 | `[二手，数字存疑]` 一份工程复盘给的**注入预算分段**：用户长期记忆 100–300 token / 最近摘要 300–800 / 检索片段 500–1500 | 数字别照抄（来源不够硬），但**"给每一段定死上限"**这个做法值得借 |

## 四、学术侧：我们的位置

`[一手]` 几篇 2025–2026 的综述与本方向的论文：

| 工作 | 是什么 | 与本页的关系 |
|---|---|---|
| **H-MEM**（Sun & Zeng, 2025）| 四层记忆 + **positional index 逐层路由**，声称在 LoCoMo 上 F1 比 5 个 baseline（含 MemGPT）高 **14.98** 点 | ★ 与我们最接近的**学术版**：都主张"**按索引逐层下钻**，而不是每次做全量相似度搜索" |
| **RAPTOR** | 递归摘要树：在摘要之上再摘要；发现"**flatten 后一起搜**"反而比"逐层树遍历"更好 | 对我们的一处提醒：**递归分层不总是优于打平** |
| **记忆综述（三篇）** | 《Memory in the Age of AI Agents》（arXiv:2512.13564，47 作者，2025-12）；《Memory for Autonomous LLM Agents》（arXiv:2603.07670）；《Anatomy of Agentic Memory》（arXiv:2602.19320）| 后者把记忆系统分成四类，其中一类就叫 **「Structured and Hierarchical Memory」** ⇒ **"记忆树"在学术分类里已经有位置** |
| **MemGPT / Letta**（arXiv:2310.08560）| "虚拟上下文管理"：core / recall / archival 三层，**由 agent 自己用工具调用来管理** | ★ **取向相反**：它的核心是"让模型自己决定搬什么"；我们的核心是"**不让模型决定**（设计期声明 + 运行期只许升）" |
| **Zep / Graphiti、Hindsight（arXiv:2512.12818）、MemoryBank、Generative Agents** | 知识图谱式 / 分层式记忆（含"反思树"、"mental models"） | 同族，但重心在**检索质量**，不在"预算与结构纪律" |

**一篇值得逐字读的**：`Memory for Autonomous LLM Agents` 把机制分成五族，
其中一族明确叫 **hierarchical virtual context** —— 那正是我们在做的事。

## 五、诚实的边界

- **这不是文献综述**：一次检索（英文为主 + 少量中文），**没有系统穷举**；
  说"没有找到"的地方，**都不能当作"不存在"**。
- **样本仍是 n = 1**：我们这套是在**一台机器、10 天**上跑出来的；
  上面那些同族实现多数是**更长周期、更多用户**的场景，**它们没崩不等于我们这套也会崩**。
- **`[存疑]` 的来源没用**：有一类"L1/L2/L3 降延迟 85%"式的文章，拿不到一手出处、
  数字过于整齐 ⇒ **只当线索，不当数据**。
- **最要紧的一条**：**结构撞车不构成正确性证据**。四家都做"索引 + 按需读"，
  说明**这条路走得通**；但它**不能证明**我们的阈值（40 行 / 4KB / 12KB）
  或我们的纪律（只许升不许降）**是对的** —— 那些仍要靠自己的实测说话。
