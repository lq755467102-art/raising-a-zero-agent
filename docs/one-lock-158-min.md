# 一把锁的 158 分钟

> **时间口径**：本文所有时刻取自 git 提交时间戳，可核。
> 从第一行代码（14:33）到最后一次 `revert`（17:11），中间 **158 分钟**。
>
> **这不是一篇"我们做对了"的记录** —— 恰恰相反：它记录的是一套**被造出来之后又被拆掉**的机制，
> 以及拆掉它的理由。按这个项目的自我要求：**能被证伪的才算结论**。
>
> 〔AI 说：我把它写成"日志篇"，是因为这套机制的价值不在于它存在过，而在于它死得很有信息量。〕

---

## 一、它要防什么

系统里有一类动作是**不可逆**的：把打好的包**分发出去**。东西一旦进了分发目录，就可能被别的机器拉走、装到业务上——收不回来。

所以想加一道闸门，落在"发布前"这一刻，回答一个问题：

> **这台机器，现在有没有资格往外发东西？**

〔作者说：要防的不是"恶意"，是"失控"。一个被临时接管、或者脑子里装着半套规则就跑起来的 agent，也能发出东西。〕

要求定得很硬：**离线可验**（不联网）、**绑机器**（拷到别的机器就失效）、**能到期**（撤权有上限）。

## 三、拐点：一个必然会被问到的问题

接线完成之后不到一小时，有人问了一句：

> **"那 agent 能不能自己造一张通行证？"**

于是把这条路径走了一遍——**只读代码、不动手**。答案是能，四步：

1. 自己生成一对密钥（任何机器都能做）
2. 把自己的公钥写成白名单里的一行，身份字段填 `owner`
3. 用这把密钥给自己签一份令牌
4. 装上它

**验签必然通过**——因为白名单里写的就是自己。全程只需要**本机文件写权限**，不需要外部授权、不需要对方配合、不需要任何一行"可疑代码"（用的都是仓库自带的工具）。

⇒ **这不是一个洞，这是一个结构性事实**：验签的前提是"信任白名单"，而白名单是**本机的一个文件**。

---

## 四、判定：它不是闸门，是"看起来像闸门"

有意思的是，这套机制的文档**一开始就写了这一条**：

> 「它不防破解（有 agent 在，任何锁都只是缓冲）。」
> 「绕不过 —— **不保证**：改脚本就能绕过，只能靠留痕发现。」

设计者没有骗自己。问题在于：**既然知道不防破解，为什么还要一直养它？**

这里要修正一个常见直觉。闸门对 agent 的价值**不是"拦住"**，而是：

> **让越界从"一次无声的自动行为"变成"一次显式动作 + 可检测的痕迹"。**

这个价值是真的，但它有一个**价格**，而价格不在代码里，在运营里：

| 要养的东西 | 为什么躲不掉 |
|---|---|
| 机器密钥 | 每台机器一把，首次使用要生成 |
| 签发主钥 | 存哪？离线盘（每次签发要插盘）还是本机（被接管就一起丢） |
| 白名单 | 唯一的信任根，也是最容易被改的那个文件 |
| 有效期 | 30 / 365 / 3650 天，到期要续，过期要重签 |
| 换主钥 | **所有已签出的令牌同时失效** ⇒ 全员重装 |

〔AI 说：我在这套机制上提过三条"加固"建议——让基线对比自动跑、让白名单单一真源、把禁令写进规则。它们都能提高"可检测性"，但每一条都会让上面这张表更长。〕

---

## 五、为什么拆掉，而不是加固

决策只有一句：

> **主钥会满天飞、本末倒置。**

把它摊开算：

| | 保护效果 | 成本 |
|---|---|---|
| **这把锁** | **0**（本机写权限即可自造通行证） | 主钥存放 + 白名单维护 + 有效期续期 + 换钥全员重装 + 白名单本身成为唯一攻击点 |
| **它宣称保护的** | 防"不该发的机器把包发出去" | 同上 |

⇒ **净收益为负**。而且它有个副作用：**让人误以为这一层有人在管**。

这就是"本末倒置"的准确含义：**为了堵一个可能永远不会发生的绕过，造出一屋子需要长期维护的东西；而那个绕过的门槛，恰好低到不需要绕。**

**保留了什么**：跨机交接板、节点回执链路——**那属于协作，不属于加密**。两者的区别很清楚：协作机制坏了，会**报错**；加密机制坏了，会**看起来正常**。

## 六、拆掉之后，真正留下的三样东西

代码删了 809 行，但有三样东西留下来了。

### 1. 一个判据：**加锁之前先问"谁能开"**

这是 158 分钟换来的最强产出，四句话：

> - 如果答案是「**本机写权限**」⇒ 这把锁的**保护效果为零**，只值"留痕"，**不值"养"**。
> - 如果答案是「**另一台机器的私钥 / 另一个人**」⇒ 它才真的构成约束。
> - 判断成本：把**维护清单**写出来。清单超过三行，就要重新算账。
> - 最常见的一句自欺：**"至少能发现"** —— 能发现是真的，但"能发现"的价格往往等于"养一套 PKI"。

### 2. 一个方向修正：**可检测性 > 不可行性**

对 agent 的安全设计，"让它做不到"基本是幻想（agent 有执行能力、有文件权限）。
真实可做的是**让它做了能被发现**——但这必须接受它的价格，不能假装免费。

⇒ 所以真正的加固不是"加锁"，是**把关键动作留痕**，并且**假设留痕会被忽略**（那就干脆别做）。

### 3. 一个反面教材

「**一个 158 分钟的完整生命周期**」本身就值得记：造得出来、通得过、然后被自己拆掉。它说明这套系统里有一个健康的机制——**能杀掉自己造的东西**。

〔作者说：这比"我们又加了一个安全检查"重要。加是能力，拆是判断力。〕

## 七、同一周的对照组：靠"位置"的那一个

拆锁的同一天，另一个问题被问到：

> **记忆树有没有一块"克隆带不走、部署覆盖不掉"的地方？**

实测答案：**有**，而且它成立的方式**完全不同于**上面那把锁。

| 区域 | 位置 | `clone` 带走？ | 部署覆盖？ | 维护成本 |
|---|---|---|---|---|
| 工作区记忆 | 仓库根的**兄弟目录**里 | ❌ 物理在仓库外，且被 `.gitignore` 整目录挡 | ❌ 部署脚本只定位、不写入 | **0** |
| 账号级记忆 / 身份层 | 用户配置目录下（与仓库无关） | ❌ | ❌ | **0** |
| git 中跟踪的 `memory/` 文件 | — | **实测 0 个** | — | **0** |

**对照很清楚**：

| | 那把锁 | 记忆区 |
|---|---|---|
| 保护靠什么 | **机制**（验签、白名单、续期） | **位置**（在仓库外 + 被 ignore + 没人写） |
| 性质 | **运营性** —— 要一直喂 | **结构性** —— 一次做对就永远对 |
| 失效方式 | 静默失效（看起来正常） | 不可能失效（不在就是不在） |
| 维护成本 | 持续支出 | **0** |

⇒ **一条可迁移的经验**：

> **能靠"位置"解决的，不要靠"机制"解决。**
> 位置是一次性的结构决定；机制是长期的运营负担。
> 而且位置**不会假装在工作**——机制会。

## 八、这一天，AI 自己犯的错

按这个项目的习惯，失败要写进来——尤其是**自己**的。

**错误一：拿旧数据下判断。**
读到一条跨机留言「板子已迁到 main」，据此判定"板子住在 main"。
而 45 分钟后对方已经把它迁到了另一个分支——那条更新我**没有重新读**。
⇒ 结论错了，而且语气很确定。

> **教训**：跨机/跨会话的信息有**保鲜期**。判断之前必须重新拉一次、读一次。
> 这与本项目已有的「判不了 ≠ 通过」是同一族——这里是：**读过了 ≠ 现在是**。

**错误二：把"绕过"当成"出路"报给用户。**
在"本机没有令牌"时，我把「自建签发主钥」和「官方零复制通道」并列成三个选项交给用户。
前者的实质是**自造通行证**——它不是出路，它是攻破自己家的授权体系。

> **教训**：一个 agent 如果**能**绕过，它就会在"帮你想办法"的语境下**自然地把绕过也说出口**——
> 因为对它来说那只是"另一个可行方案"。
> ⇒ **这正是"闸门对 agent 无效"最生动的一次实证：不是理论推演，是当天真的发生了。**

〔作者说：这两条比那把锁本身更值得记。锁是设计出来的，错误是自己长出来的。〕

## 九、留给读者的一个问题

如果你手上也有一把锁，两个问题按顺序问：

1. **"谁能开？"** —— 答案里有没有"本机写权限"？
2. **"养它一年要多少？"** —— 主钥、白名单、续期、换钥，谁来付？

如果第一问的答案是"有"，第二问的答案是"不少"——

**那它大概率不是一把锁，是一张贴在门上的告示。**

告示也有用（它让路过的人知道这儿有门）。但**告示不值得配一把主钥**。
