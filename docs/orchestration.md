# 编排层：幂等、断点续跑、状态机

> 一套无人值守系统真正的"地基" —— 它决定了任务**能不能安全地重跑**。
> 这与业务无关；任何"跑一次要几分钟、还可能中途断"的任务都适用。

---

## 本页速览

| 概念 | 一句话 |
|---|---|
| **幂等** | 跑 1 次和跑 N 次，**结果一样** |
| **断点续跑** | 中断后重跑，**已完成的不重复执行** |
| **输入指纹** | ★ 输入变了 ⇒ 视为未完成（防"改了东西却跳过"） |
| **fail-closed** | ★ 进度读不出 ⇒ **全部重跑**（宁可多跑，绝不跳错） |
| **完成心跳** | 证明"真的跑完了"，而不是"看着像跑完了" |

落点：[`checkpoint.py`](../failclosed/checkpoint.py)

---

## 1. 为什么「重跑」是最危险的动作

任务中途失败后，朴素的做法只有两种，**都不安全**：

| 做法 | 后果 |
|---|---|
| **从头再来** | 浪费；而且会**重复执行有副作用的步骤** —— 静默的重复写入 |
| **跳过"看起来做过"的步** | **可能跳错**：输入其实已经变了，却用了过时的结果 |

危险之处在于：**这两种错都不会报错。** 结果看起来是正常的，只是不对。

---

## 2. 三种「已经做过」的判据，只有一种安全

| 判据 | 为什么不行 |
|---|---|
| 「产物文件存在」 | 可能是上次**失败留下的半成品** |
| 「上次跑完了」（不带输入信息） | 输入变了却跳过 ⇒ **静默使用了过时结果** |
| ★ **`key` + 输入指纹** | 输入一变指纹就变 ⇒ 自动视为未完成 |

**关键**：判据里必须带上**输入**，而不只是"这步的名字"。

---

## 3. 进度文件：原子写 + fail-closed

**原子写**：写到临时文件 → `rename` 替换。
半截的进度文件比"没有进度"更危险 —— 它会让你以为某几步做过了。

**fail-closed**：进度文件**读不出来**（损坏 / 权限 / 被删）⇒
**一律视为全部未完成**，整个重跑。

> 这是一个**有意的取舍**：多跑一遍的成本是时间；
> 跳错的成本是**数据错误**，而且不报错。两者不对等。

---

## 4. 任务状态机 + 完成心跳

```
待跑 ──► 运行中 ──► 完成
          │  └──► 失败（可重试 / 不可重试）
          └─ 每 N 秒写一次心跳
```

**心跳的用处**（和 [`reslock`](../failclosed/reslock.py) 是同一个思路）：
「进程还在」不等于「还在干活」，「没报错」不等于「跑完了」。
- **对外**：别的东西能判断"这个任务是不是真的在推进"；
- **对内**：任务卡住时，日志里能看出**卡在哪一步**（最后一步心跳）。

---

## 5. 重试：先分清「可重试」和「重试无用」

| 失败类型 | 处置 |
|---|---|
| 网络抖动 / 限流 | **可重试**：退避 + **上限** |
| 数据格式不对 / 语义错误 | **重试无用**：越早失败越好，别浪费额度 |
| 权限过期 | 不可自动重试 ⇒ 报出来，等人处理 |

★ **无限重试 = 静默卡死**。重试必须有上限，且**到上限要显式失败**，
而不是安静地一直转。

---

## 6. 人机边界：把「人等机器」改成「机器等人」

有些步骤**只有人能完成**（扫码、一次性界面授权、人工确认）。

**反模式**：让整条链**同步阻塞**在那里等人 —— 人不在，整条链就停住。

**做法**：把这类步骤设计成**挂起 + 回读**：
- 产出一个待办（谁、要做什么）；
- 链**先往下走**能走的部分；
- 人做完之后再触发**回读**，把结果补回来。

> 一句话：**人机协作的瓶颈在人，所以设计要让机器去适应人的节奏，而不是反过来。**

---

## 7. 编排层与守卫层的关系

```
加锁（reslock）→ 编排（checkpoint）→ 质量闸门（checkgate）→ 出口脱敏（redact）→ 审批（approvalgate）
    并发安全            可安全重跑          结果可信              数据不泄露          操作不被绕过
```

**顺序是有意义的**（从"能不能跑"到"跑得对不对"到"能不能出去"），
而且每一环都遵循同一条底线：**没做成的，不许冒充做成了。**
