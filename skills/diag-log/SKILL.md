# 机群异常上报

> **一句话**：**遇到异常的机器自己说一句话** —— 落到共享表 + 即时推给维护者，
> 免得维护者挨台去问「你最近过得怎样」。

## 为什么需要它

系统是**分布式**的（维护者的机器 / 工作机 / 备用机 / 协作者机 / 用户机）。
「登录过期、页面改版、绑定失败、抓取 0 行」这类问题**只发生在那一台机器上** ——
不主动上报，维护者就只能等哪天自己撞上。**异常只在发生时的那台机器上可见。**

## 何时用

**收尾判断**：本轮是否「没按预期走完」或「走完了但结果可疑」？是 ⇒ 报一条。

| 症状 | 级别 |
|---|---|
| 登录过期 / 要重新扫码 | 异常 |
| 页面改版 / 找不到元素 / 点不到按钮 | 异常 |
| 绑定、加表失败（计数没涨、账号找不到） | 异常 |
| 抓取 0 行 / 数据对不上（数目不对、报表空） | 异常 |
| 工具或脚本报错（非 0 退出码、堆栈） | 异常 |
| 桥接 / 后台进程不可用且自动拉起失败 | 异常 |
| 能跑但有偏差（重试多次才成功、耗时异常长） | 警告 |
| 只留个痕迹（可选） | 信息 |

**不要报**：正常成功的每一轮（那是噪音）；用法错误（参数写错）；
**12 小时内同机器同技能同摘要**（脚本自动去重）。

## 怎么跑

```bash
# 上报一条（主用法）
"{{PY}}" "{{WB_ROOT}}/diag-log.py" --skill "某流程①" --level 异常 \
  --msg "登录过期，页面跳到登录页" --detail "账号 12345678，重试 2 次仍失败"

# 只看会写什么 / 会推什么（不写不推）
"{{PY}}" "{{WB_ROOT}}/diag-log.py" --skill X --level 异常 --msg "..." --dry-run
# 体检本机配置（表配没配、通道通不通）
"{{PY}}" "{{WB_ROOT}}/diag-log.py" --check
# 汇总端（**只在主控机器**有意义）：补推「未推送」的条目
"{{PY}}" "{{WB_ROOT}}/diag-log.py" --digest [--dry-run]
```

## 输出（一行 JSON）

```json
{"ok":true,"stage":"reported","table":"已写入","pushed":true,"pushBy":"webhook（…）"}
{"ok":true,"stage":"skipped","reason":"dedupe"}   ← 12h 内报过同一条，正常
{"ok":true,"stage":"skipped"}                     ← 未配表 / 未配通道，**不算失败**
```

## ★ 三条硬规矩

1. **它是"顺带做的事"，不是主任务** —— 任何失败都 **exit 0**；
   **不要**因为"日志写失败"而让技能失败，也**不要**重试、不要卡住流程。
   如实照常汇报技能本身的结果即可。
2. **只在真异常时报** —— 别把每轮成功也报一遍（表会变垃圾、维护者手机会变噪音）。
   同类异常 12 小时内自动去重。
3. **`--msg` 是会被推到手机的** —— 一句话说清症状；细节放 `--detail`。
   ⚠ 表在**共享空间**（同事可见）⇒ **`--detail` 里别写与排查无关的敏感内容**。

## 配置（本机文件，**不入库**）

| 项 | 位置 | 缺了会怎样 |
|---|---|---|
| **机器名** | 本机配置 `machineLabel` | 兜底链：`machineLabel` → `<账号标识>-机` → `机器-<设备号前 6 位>`（仍可区分，但**不可读**）。★ 建议每台机取个**不重名**的好名字 |
| 日志表 ID | 本机配置 | 只推送、不写表（仍能在手机看到） |
| 推送地址 | **共享文档里的配置项**（脚本自动取 + 7 天缓存） | 只写表、不推送（维护者去文档看） |
| 本机覆盖（可选） | 本机通知配置 | 留空即走上面的共享文档（**推荐留空**） |

**机器名一句话**：表里「是哪台机器」由 `机器`（名字）/ `角色` / `使用者` /
**`设备`（设备号前 8 位，唯一）** 四列界定；推送正文另附一行设备号 —— **同名机器也能一眼区分**。

① 表必须建在**共享空间**（团队成员有编辑权）—— 建在个人空间员工写不进来
（**权限只能人工设**，脚本做不到）。
② **员工机零配置**：表 ID 与推送地址都从共享文档自动取（该文档放在**只读**空间 ⇒
员工能读、改不了）；维护者换机器人 / 换表**只改那个文档**，全机群跟着变（缓存最多滞后 7 天）。

## 这个模式为什么值得抄

**它把"分布式系统里最难的一件事"变简单了**：

| 难点 | 解法 |
|---|---|
| 异常只在某一台机器上可见 | **让那台机器自己上报**，不靠人去问 |
| 上报本身会拖慢/搞挂主流程 | **它是顺带的，失败也 exit 0** —— 上报的成败**不影响**主任务 |
| 员工机零配置、不想改东西 | 配置**集中在共享文档** ⇒ 改动一处、全机群生效 |
| 分不清是哪台机器 | **设备号做唯一标识**（同名也不怕） |
